## Production build limitation (environment, not code)

`next build` cannot complete in this sandbox: Next's final cleanup step deletes temp
files, which trips the agent's `[safe-delete] SAFE_DELETE_BULK_CONFIRM_REQUIRED`
guard (50 deletions/turn) — or the trash shim times out (ETIMEDOUT).
A partial run DID reach "✓ Compiled successfully" and "✓ Generating static pages (3/3)",
so the code itself is production-valid.

Workaround added: `next.config.mjs` now honours `NEXT_DIST_DIR` (default `.next`).
Use `NEXT_DIST_DIR=".build-prod" npx next build` to avoid wiping `.next`.
Turbopack REFUSES a distDir outside the projectPath (no `../../` escape).
Run real builds in the user's own terminal before deploying.
